# Kyusu operations

Generated by `kyusu_batch --reference`; do not edit by hand.

## Assets

- `assets.list` query — The project's content files a query finds, best match first, as the asset shelf finds them: words a name or path must hold, 't:<kind>' for a kind ('t:material', 't:scene') and 'in:<folder>'.
  - `query` string, default '' — what to look for; everything when empty
  - `limit` int, default 50 — most files to list
  - answers: assets, truncated

## Brush

- `brush.box` mutation — Adds a solid box brush between two corners, as one undoable step: a pillar, a ledge, a crate. Its faces take the project's floor, ceiling and wall materials by which way they face.
  - `min` [x, y, z] — one corner
  - `max` [x, y, z] — the opposite corner
  - `name` string — what to call it; the next free 'Brush' name when absent
  - answers: created, modified, deleted, walls, revision, brush
- `brush.carve` mutation — Cuts a rectangle or an arch into the face of a brush at a point, through the brush or as a recess, as one undoable step: a window in a detached wall, an alcove, a hole in a floor. The shape stands upright on a wall. Doors in generated walls are opening.create.
  - `subject` string — a brush's id or '@<name>'
  - `at` [x, y, z] — the middle of the cut, on the face
  - `width` number — metres across
  - `height` number — metres up the face
  - `shape` rectangle|arch, default 'rectangle' — the outline
  - `rise` number, default 0.5 — an arch's curve as a share of its height, 0 to 1
  - `through` bool, default true — cut through to the far side; a recess otherwise
  - answers: created, modified, deleted, walls, revision
- `brush.clip` mutation — Cuts brushes with a plane, as one undoable step, keeping the side the normal points to, the other side, or both as separate brushes. A kept part that comes apart becomes a brush per part.
  - `subjects` list of string — the brushes to cut
  - `point` [x, y, z] — a point on the cutting plane
  - `normal` [x, y, z] — the plane's front direction
  - `keep` front|back|both, default 'front' — what stays
  - `cap` bool, default true — close the cut faces
  - answers: created, modified, deleted, walls, revision, pieces
- `brush.extrude` mutation — Pulls the face of a brush that looks toward a direction out by a distance, growing a new cap and side walls, as one undoable step: a step, a lip, an arm of an L.
  - `subject` string — a brush's id or '@<name>'
  - `face` north|south|east|west|up|down — the face looking this way
  - `distance` number — metres outward; negative pushes in
  - answers: created, modified, deleted, walls, revision

## Draft

- `draft.accept` session — Applies a draft to the level it copies as one undoable step, and drops it. Refused when the level has changed under any entity the draft changes; rebase it then.
  - `draft` string, optional — the draft's id; the one being written when absent
  - answers: created, modified, deleted, walls, revision
- `draft.begin` session — Copies the focus level into a new draft. Mutations edit the draft until it is accepted, discarded, or another draft is written; queries read it too.
  - `label` string — what the draft proposes, in a few words
  - `rationale` string, optional — why
  - `id_seed` int, optional — what the ids it mints follow from; random when absent
  - answers: draft, base, id_seed
- `draft.diff` query — What a draft changes against the level it copies, and the steps that changed it.
  - `draft` string, optional — the draft's id; the one being written when absent
  - answers: created, modified, deleted, walls, draft, label, rationale, base, state, failure, steps
- `draft.discard` session — Drops a draft; the level never saw it.
  - `draft` string, optional — the draft's id; the one being written when absent
  - answers: draft
- `draft.list` query — Every open draft, which one is being written and which is shown.
  - answers: drafts
- `draft.open` session — Replays a proposal file into a new draft of the focus level, which must be the level it was written for, and names the entities that level has changed since.
  - `path` string — the proposal file
  - answers: created, modified, deleted, walls, draft, label, rationale, author, state, failure, moved_since, changed_operations
- `draft.preview` session — Shows the named draft over its level in Kyusu, ghosted, or none when no draft is named.
  - `draft` string, optional — the draft's id; absent shows none
  - answers: previewed
- `draft.rebase` session — Replays a draft's steps on a fresh copy of its level, taking in everything that changed there since, and the steps of a proposal whose replay stopped short. Refused, leaving the draft as it was, when a step does not apply.
  - `draft` string, optional — the draft's id; the one being written when absent
  - answers: created, modified, deleted, walls
- `draft.resume` session — Lets a failed draft take steps again, from what the steps before the refused one made. Refused for a proposal whose replay stopped short; rebase or discard that.
  - `draft` string, optional — the draft's id; the one being written when absent
  - answers: draft
- `draft.save` session — Writes a draft as a proposal file: its steps, the level they apply to, what the entities they change or rely on looked like, and the operations' contracts, for a designer to open and review.
  - `draft` string, optional — the draft's id; the one being written when absent
  - `path` string — the file to write, by convention <project>/.proposals/<name>.sproposal
  - `author` string, optional — who proposes it
  - answers: draft, path, steps
- `draft.write` session — Makes mutations edit the named draft, or the level itself when no draft is named.
  - `draft` string, optional — the draft's id; absent for the level
  - answers: writing

## Level

- `changes.mark` query — Remembers the level as it is now, for changes.since to compare against. The newest 16 marks are kept.
  - answers: mark
- `changes.since` query — What was created, changed and deleted in the level since a mark, by anyone, and a mark for now.
  - `mark` string — from changes.mark or an earlier changes.since
  - answers: mark, created, modified, deleted
- `component.set` mutation — Sets one field of one of an entity's components, as one undoable step: a light's intensity, a space's wall thickness. Components and fields are named as entity.describe shows them; a nested field is named with dots. The value must be the kind the field already holds.
  - `subject` string — an entity id or '@<name>'
  - `component` string — the component's key, as entity.describe lists it
  - `field` string — the field, e.g. 'thickness' or 'color.r'
  - `value` string — the new value as JSON: 0.5, true, [1, 0, 0], "text"
  - answers: created, modified, deleted, walls, revision, stored
- `conventions.get` query — The project's blockout conventions: wall thickness, opening size, space height and material roles, from its level.conventions asset or the defaults when it has none.
  - answers: asset, values, problems
- `entity.delete` mutation — Deletes entities and everything under them, as one undoable step. A space's doors go with it; walls it shared are rebuilt for its neighbours.
  - `subjects` list of string — what to delete
  - answers: created, modified, deleted, walls, revision
- `entity.describe` query — One entity in full: its components as JSON, its parent and children, and its brush's size. The subject is an entity id or '@<name>'.
  - `subject` string — an entity id or '@<name>'
  - answers: entity, parent, children, components, brush
- `entity.duplicate` mutation — Copies entities and everything under them, offset by a vector, as one undoable step. Copies take fresh ids and the next free names.
  - `subjects` list of string — what to copy
  - `offset` [x, y, z] — metres from each source to its copy; none when absent
  - answers: created, modified, deleted, walls, revision, copies
- `entity.rename` mutation — Gives an entity a new authored name, as one undoable step. Surrounding spaces are trimmed and an empty name clears it.
  - `subject` string — an entity id or '@<name>'
  - `name` string — the new name; empty clears it
  - answers: created, modified, deleted, walls, revision
- `entity.reparent` mutation — Moves entities under a new parent, or to the top of the level, as one undoable step. By default they stay where they are in the world.
  - `subjects` list of string — what to move
  - `parent` string, default '' — an entity id or '@<name>'; empty for the top of the level
  - `keep` world|local, default 'world' — what the move preserves
  - answers: created, modified, deleted, walls, revision
- `instance.place` mutation — Places a scene (a prefab: a turret, a lamp, a door frame) at a point, turned about up, as one undoable step. Its entities follow the source; edits to them are kept as the placement's overrides.
  - `source` string — the scene's asset path, as assets.list finds it with 't:scene'
  - `at` [x, y, z] — where its origin goes
  - `turn` number, default 0 — degrees counter-clockwise seen from above
  - answers: created, modified, deleted, walls, revision, placement
- `level.summary` query — Counts, overall bounds and one line per entity of the focus level, leaving out the wall brushes spaces built (deps on a space counts them).
  - `limit` int, default 200 — most entities to list
  - answers: document, entity_count, brush_count, wall_count, min, max, entities, truncated
- `measure.clearance` query — The floor, ceiling and free width around a point in a passage, measured against the visible brushes; width is taken across the direction of travel at body height. With navigation settings, says whether the profile's capsule fits. Null means nothing bounds that side within 100 m.
  - `point` [x, y, z] — a world position inside the passage
  - `direction` [x, y, z], optional — horizontal direction of travel; north (-z) when absent
  - answers: floor, ceiling, height, width, profile
- `nav.reachable` query — Whether the walkable surface connects two points, asked twice: with only the held traversal kinds, and with every kind the scenario leaves unknown as well. Reached and unreached are verified under the stated assumptions; depends_on names the unknown kinds the cheapest open route crosses.
  - `from` [x, y, z] — world position
  - `to` [x, y, z] — world position
  - `held` list of string — traversal kinds the player can perform, e.g. navigation.traversal.jump
  - `denied` list of string — traversal kinds the player cannot perform
  - `profile` string, optional — navigation profile; the first one when absent
  - answers: outcome, depends_on, sure, possible, route, assumptions, profile, from, to
- `plan.section` query — A floor plan: every brush cut by a horizontal plane, as outlines of [x, z] points (north is -z), plus the entities with a place but no extent. Optionally written as a north-up PNG with a metre grid. Cut off floor and ceiling planes, e.g. at eye height.
  - `height` number, default 1.5 — world height of the cut, metres
  - `image` string, optional — a path to write the plan to as PNG
  - `pixels_per_metre` number, default 16
  - `max_side` int, default 2048 — longest image side in pixels
  - answers: height, brushes, points, min, max, image
- `query.box` query — Entities whose bounds touch an axis-aligned box.
  - `min` [x, y, z] — one corner
  - `max` [x, y, z] — the opposite corner
  - `limit` int, default 200 — most entities to list
  - answers: entities, truncated
- `query.near` query — Entities within a radius of a point, nearest first, with distance to their bounds and compass bearing.
  - `point` [x, y, z] — where to look from
  - `radius` number, default 8 — metres
  - `limit` int, default 50 — most entities to list
  - answers: entities, truncated

## Material

- `material.apply` mutation — Paints brushes with a material, every face or only the face toward a direction, as one undoable step. A space's faces are the inner faces of its walls.
  - `subjects` list of string — the brushes to paint
  - `material` string — a material's asset path, as assets.list finds it
  - `face` north|south|east|west|up|down — only the face looking this way; every face when absent
  - answers: created, modified, deleted, walls, revision

## Note

- `note.add` mutation — Leaves a note in the level, as one undoable step: about an entity, parented to it so it follows, or at a point. Notes are authoring only; the cook strips them.
  - `text` string — what to say, at most 255 characters
  - `subject` string — the entity it is about; absent for a point
  - `at` [x, y, z] — where it stands; the subject's position when absent
  - `author` string, default 'claude' — who leaves it
  - answers: created, modified, deleted, walls, revision, note
- `note.resolve` mutation — Marks a note resolved, or open again, as one undoable step.
  - `subject` string — a note's id or '@<name>'
  - `state` resolved|open, default 'resolved'
  - answers: created, modified, deleted, walls, revision
- `notes.list` query — The level's notes, the open ones unless asked otherwise, with what each is about.
  - `state` open|resolved|all, default 'open'
  - answers: notes

## Space

- `deps` query — What follows from an entity and would change with it. For a space: how many wall brushes it built, the openings cutting them, the spaces it shares a wall with, and the spaces its doors lead into. For an opening: the spaces whose walls it cuts and the spaces it joins.
  - `subject` string — an entity id or '@<name>'
  - answers: subject, walls, cut_by, shares_walls_with, leads_to, cuts, joins
- `level.diagnostics` query — What is wrong with the level's spaces and openings: refused or approximate shells, spaces that overlap, openings that could not be cut, lead into no space, or are too small for the navigation profile's capsule. Each record is about an entity, by persistent id.
  - answers: records
- `opening.create` mutation — Cuts a door or window through the generated wall at a point, owned by the space whose wall it is. A sill of zero, the default, makes a doorway down to that wall's floor.
  - `at` [x, y, z] — a point in or near the wall; the opening is centred across from it
  - `sill` number, optional — metres above the wall's floor; 0 when absent
  - `width` number, optional — metres; the project's opening width when absent
  - `height` number, optional — metres; the project's opening height when absent
  - `shape` rectangle|arch, optional — rectangle when absent
  - `name` string, optional — what to call it; after its space when absent
  - answers: created, modified, deleted, walls, revision, opening, space
- `opening.move` mutation — Slides an opening by an offset; the walls it cuts follow it.
  - `subject` string — an opening's id or '@<name>'
  - `offset` [x, y, z] — metres to move by
  - answers: created, modified, deleted, walls, revision
- `shell.detach` mutation — Stops a space building its walls: its wall brushes stay as they stand, openings already cut, as ordinary brushes under the space. The space, its name and its openings stay. Undo brings the shell back.
  - `subject` string — a space's id or '@<name>'
  - answers: created, modified, deleted, walls, revision
- `shell.rebuild` mutation — Rebuilds a space's walls from its volume, taking back the wall brushes edited by hand and kept, as one undoable step. Paint on the walls stays.
  - `subject` string — a space's id or '@<name>'
  - answers: created, modified, deleted, walls, revision
- `space.create` mutation — Adds a named box-shaped space between two corners, with generated walls unless asked not to. Its faces take the project's floor, ceiling and wall materials.
  - `name` string — what to call it, unique in the level
  - `min` [x, y, z] — the corner with the lowest x, y and z; y is the floor
  - `max` [x, y, z] — the opposite corner; y is the ceiling
  - `shell` bool, optional — generate walls; true when absent
  - `thickness` number, optional — wall thickness in metres; the project's when absent
  - answers: created, modified, deleted, walls, revision, space
- `space.graph` query — Which spaces the walkable surface joins, measured on the level's navigation under a scenario: a connection is reached when the sure walk makes it and depends_on when only the possible walk does. Also whether walkable surface runs through each opening, and which spaces have none.
  - `held` list of string — traversal kinds the player can perform, e.g. navigation.traversal.jump
  - `denied` list of string — traversal kinds the player cannot perform
  - `profile` string, optional — navigation profile; the first one when absent
  - answers: spaces, connections, openings, complete, assumptions, profile
- `space.move` mutation — Moves a space and what it owns. With carry, the default, each door it owns pulls the face of the space on the far side by the move's part along that face, so a corridor stretches or shrinks to stay attached. A sideways move cannot be carried and leaves the door off the corridor's end; a far side whose walls were detached is skipped and named.
  - `subject` string — a space's id or '@<name>'
  - `offset` [x, y, z] — metres to move by
  - `carry` bool, optional — pull the spaces its doors open onto; true when absent
  - answers: created, modified, deleted, walls, revision, carried, skipped
- `space.propose` mutation — Proposes spaces for walkable surface no space holds yet, read off the level's navigation: a room wherever the floor runs at least core_depth from any edge, a passage for the walkable surface left between. A heuristic: run it in a draft and check the plan before accepting. The spaces are made without generated walls, since the level already has its own.
  - `core_depth` number, default 1 — metres from the edge of walkable surface a room's middle reaches
  - `height` number, optional — metres from floor to ceiling; the project's space height when absent
  - `profile` string, optional — navigation profile; the first one when absent
  - answers: created, modified, deleted, walls, revision, proposed
- `space.resize_face` mutation — Pushes the face of a space that looks toward a compass direction outward by a distance, or pulls it in with a negative one. Its walls follow.
  - `subject` string — a space's id or '@<name>'
  - `face` north|south|east|west|up|down — the face looking this way
  - `distance` number — metres outward; negative pulls it in
  - answers: created, modified, deleted, walls, revision

## View

- `view.context` query — What the designer is looking at in the running editor: the active view's eye and compass facing, the surface at the middle of the view, the space the eye is in, the spaces in view (nearest first) and the selection.
  - `limit` int, default 32 — most spaces in view to list
  - answers: camera, aim, in_space, in_view, truncated, selection
- `view.frame` query — Turns the active view onto subjects, or onto the selection when none are named, without changing the selection.
  - `subjects` list of string — what to frame; the selection when empty
  - answers: camera
- `view.select` session — Selects entities in the running editor, as one undo step, and frames them in the active view when asked. No subjects clears the selection.
  - `subjects` list of string — what to select
  - `frame` bool, default false — also frame them in the active view
  - answers: selection, framed

## World

- `diagnostics` query — What the world's validation reports: each record's severity, stable rule id, the kind and id of what it is about, and a message.
  - answers: records
- `dock.place_at` mutation — Adds a dock to the world scene fitted to an opening, or to a crossing world.crossings reported, as one undoable step. The dock keeps no tie to what it was fitted to. The world scene must be focused (world.focus target=world); a draft of it proposes the dock instead.
  - `opening` string — an opening's id or '@<name>', in any open zone
  - `at` [x, y, z] — the middle of the crossing on the floor, without an opening
  - `width` number — metres, without an opening
  - `facing` north|south|east|west|up|down — the way out of the zone it leaves, without an opening
  - `height` number — metres; the opening's, else 3
  - answers: created, modified, deleted, walls, revision, dock
- `world.bypasses` query — The gated docks the sure walk from a point gets to both sides of with every gate shut that is not assumed open: what the gate was meant to keep back is reachable some other way. Opens every zone.
  - `from` [x, y, z] — world position
  - `held` list of string — traversal kinds the player can perform, e.g. navigation.traversal.jump
  - `denied` list of string — traversal kinds the player cannot perform
  - `profile` string, optional — navigation profile; the first one when absent
  - `open_gates` list of string — gated docks assumed open, by dock id
  - `closed_gates` list of string — gated docks assumed shut, by dock id
  - answers: bypasses, complete, unconsidered
- `world.crossings` query — Where a zone's walkable surface runs to its bounds with another zone beyond and no dock between the two covers it (spatial.crossing_without_dock). Each crossing gives the point, width and facing dock.place_at takes. A closed zone named is opened; 'confirmed' says whether the zone beyond, when open, walks on from there too.
  - `zone` string — a zone's id or name; the focused zone when absent
  - answers: crossings
- `world.focus` session — Chooses which document of the world the level operations read and write: a zone, by id or name, or 'world' for the world scene, which holds the docks. Opens the zone when it is closed. Live, it moves the designer's focus too.
  - `target` string — a zone's id or name, or 'world'
  - answers: focus
- `world.reachable` query — Whether one point of a world reaches another, across zones, asked twice like nav.reachable. A zone is left only through a dock: by walking to its mouth, crossing it the ways it allows, and landing where it puts you, so a dock in a floor is a drop. A gated dock counts as shut in the sure walk unless assumed open. World links have no positions yet and are listed as unconsidered. Opens every zone.
  - `from` [x, y, z] — world position
  - `to` [x, y, z] — world position
  - `held` list of string — traversal kinds the player can perform, e.g. navigation.traversal.jump
  - `denied` list of string — traversal kinds the player cannot perform
  - `profile` string, optional — navigation profile; the first one when absent
  - `open_gates` list of string — gated docks assumed open, by dock id
  - `closed_gates` list of string — gated docks assumed shut, by dock id
  - answers: outcome, depends_on, depends_on_gates, legs, docks, unconsidered, assumptions, profile
- `world.summary` query — The world's zones, which one the level operations read, and the docks between them: where each stands, which way it faces and how big it is.
  - answers: name, start_zone, zones, docks
