# Lightmap atlas: Phase 0 spike evidence

The Phase 0 gate from the lightmap plan: do chart-grown, atlas-packed lightmaps
over kyusu mesh geometry (curved soft-edged surfaces, hard-edged recesses,
instanced placements) look right and behave deterministically, before the real
format bump and cook replacement are built? Spike branch: `lightmap-spike`
(code harvested, not merged; the vertex format is NOT bumped here — the
existing 4-byte vertex slot is reinterpreted as two unorm16 UVs).

## Scene

Generated by `test/level_cook/LightmapSpikeGen.cpp` (env-gated,
`SENCHA_LIGHTMAP_SPIKE_ROOT`): a floor slab; a corner block whose vertical
edge is beveled into a quarter round (8 planar segments) with dihedral-under-45
edges softened (the chart-continuity risk); a hard-edged pillar wall with two
proud pillars (chart cuts + occlusion); one Direct point light inside the
curve; one Direct spot raking the pillars. Cooked at luxel 0.25 (default) and
0.5 (`lightmap_spike` / `lightmap_spike_coarse`). Three placements of a
scripted tile mesh with [0,1] lightmap UVs fake the instanced-placement leg
(per-instance atlas rects via a marked extraction hack on the spike branch).

## Results against the gate

1. **Curve continuity** (`phase0_scene_luxel_0p25.png`): the 8-segment arc
   reads as one continuous smooth wash. No chart seams, no banding, no
   faceting. The union-find + cone-split chart generator held.
2. **Buried-luxel shadow bleed, found and fixed.** First capture showed dark
   halos leaking out from under wall bases: the floor chart continues under
   overlapping brushes (kyusu never carves), those luxels bake black, and
   bilinear filtering drags the black past the base. Fixed in the rasterizer
   with buried-sample invalidation: a luxel whose first hit along its own
   normal is a BACKFACE (BakeBvh::FirstHitIsBackface) is inside/under solid,
   so it stays uncovered and dilation continues the neighboring lighting
   across it. Legitimate shadows (open air above) are untouched; the pillar
   recess shadows survive crisp. This fix is mandatory for v1: brush overlap
   is the normal kyusu authoring style.
3. **Hard edges**: pillar/wall charts cut at hard edges; occlusion shadows
   resolve at luxel fidelity with no visible speckle at 0.25 (fixed 2x2
   supersampling NOT adopted; revisit only if real content shows speckle).
4. **Atlas health** (`phase0_atlas_0p25.png`, decoded from the cooked .stex):
   floor chart with pillar shadow bands and the buried-luxel bite under the
   corner block; the whole arc as ONE chart; shelf packing with 2-texel
   gutters; reserved black border row/column. 256x128 RGBA8 = 131 KB at 0.25;
   128x128 = 65 KB at 0.5 (`phase0_atlas_0p50.png`).
5. **Instancing + exclusion** (`phase0_capture_orbit.json`, scripted-orbit
   capture): max-visibility frame shows **6 objects -> 4 draws** (3 unique
   cells + ONE instanced draw for the 3 tile placements, each sampling a
   distinct atlas rect through the per-instance scale/bias), and
   `lights_visible_count 0 / lights_dropped_at_cap_count 0` on every frame:
   the entire scene is lit by the atlas alone.
6. **Determinism**: two independent cooks of the level produced byte-identical
   `.smesh` and `lightmap.stex` artifacts (`diff -r` clean).
7. **Cook cost**: the full spike cook (charts + pack + raster + bake, both
   variants) runs in ~65 ms inside the generator test.

## Known items carried to the real build (Phases 1+2)

- Formal render A/B bench (p50/p99 vs main via `scripts/bench_render_ab.sh`)
  runs at the Phase 1+2 merge gate; the spike's raster load is far below the
  measured 49.7k-tris-at-0.041ms precedent, so perf was not the spike risk.
- One non-reproducible shutdown segfault after a capture run: TextureCache
  freeing a live entry into a destroyed VulkanDescriptorCache during game.so
  static teardown. The spike deliberately leaks one atlas ref (no
  ZoneLightmapComponent release traits yet); Phase 1's traits remove the leak.
  Revisit if it recurs after that.
- In-engine debug-view screenshots (baked_direct / lightmap_texels) owed: the
  SceneViewer free-cam pose depends on cursor position, so unattended captures
  drift; the decoded-atlas PNGs cover the same diagnostic for the spike.
- `render.baked_direct.enabled 0/1` A/B and the kyusu PIE path smoke run land
  with Phase 2's cook tests.

## Reproduce

    cmake --build build --target level_cook_tests app
    SENCHA_LIGHTMAP_SPIKE_ROOT=$(pwd)/template/assets ./build/test/level_cook_tests \
      --gtest_filter='LightmapSpike.Generate'
    cd template && SENCHA_PRESENT_MODE=IMMEDIATE ../build/example/SceneViewer/app \
      +set sceneviewer.camera.scripted 0 +map levels/lightmap_spike \
      +set render.ambient.sky_r 0.03 +set render.ambient.sky_g 0.03 +set render.ambient.sky_b 0.04
